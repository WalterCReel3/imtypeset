# advtext-rework-plan — core API requests (builder, 2026-10-10)

What the two spikes (pptmstr's real pane through `python/spike_bundle/pptmstr_overlay/`, advtext's
real document through `python/spike_advtext/`) asked of the core and its Python package, each with
the measurement behind it. Numbers are from `python/spike_bundle/results/*.jsonl`; microseconds
unless said; Xvfb + llvmpipe at load 4 to 12. Ordered by what a user of either application would
notice. None blocks "Start here".

| | request | measured behind it | where it would land |
|---|---|---|---|
| **C1** | **Draw into the current window without the host finding the draw list.** `Document.draw(None, pos)` or `imtypeset.window_draw_list()`. | Both applications reach `ImGui::GetWindowDrawList` through `ctypes.CDLL(<wheel binary>)._ZN5ImGui17GetWindowDrawListEv` (pptmstr's `ui/typeset.py`, `views.py`, `examples/python/bundle_support.py`): a mangled name of one compiler, in application code. No speed in it (an empty library call is 230 to 270 ns). `python/imtypeset/_bundle.py` already knows the symbol. | `python/imtypeset` (bundle branch), or a null `draw_list` in `DrawDocument` |
| **C2** | **Say how much the height above the window changed, or keep the window still.** e.g. `ImTypesetDocumentStats::HeightChangeAbove`, or a draw flag that anchors. And better estimates for prose: today a paragraph's estimate ignores its width. | Code blocks: 0 of 622 estimates wrong. Paragraphs and list items: 244 of 815 wrong by 16 to 48 px at the largest session (net 3,988 of 102,796 px); 589 of 1,204 on the prose corpus, worst 97 px (net 11,387 of 94,337 px). Scrolling the largest session by wheel: the content height changed on 81 frames, 512 px at most; advtext x10: 45 frames, 44 px at most. A host cannot anchor what it is not told. Settling everything instead costs 7.7 ms (118 blocks), 66 ms (1,442), 97 ms (1,180 prose-light x10). | `src/imtypeset_document.*`, `src/blocks.*` (`estimate`) |
| **C3** | **Find in the library, or marks from a packed buffer.** `FindInDocument(needle, case-insensitive) -> ranges`, or `pack_marks` taking `struct`-packed bytes. | pptmstr, 523 KB transcript: a keystroke that matches 2,000 times costs 9.7 to 13.8 ms, nearly all of it Python: `str.find` over folded copies of every block and one ctypes struct write per mark in `pack_marks` (about 5 us a mark). With few matches 1.6 to 3.0 ms. advtext x10 (55 KB): 0.7 to 18 ms. D43 records find as a gap, not a decision. | `python/imtypeset/__init__.py` (`pack_marks`) first; the core if a host other than Python wants it |
| **C4** | **Copying a range should not lay out the blocks strictly inside it.** Their text is known without lines. | `range_text` over a whole 523,223-character document: 15.2 ms when every block is laid out, 45 to 119 ms when not (it lays out all 1,442: `BlocksLaidOut` goes from 45 to 1,451). advtext x10: 5.6 to 7.5 ms either way (370 blocks). This is "copy visible" and select-all on a long transcript. | `AppendDocumentRangeText` |
| **C5** | **Tables (R6).** | The only construct that did not fit in either application: 95 of 13,074 pptmstr blocks, 9 of 157 advtext blocks (129 cells). In pptmstr the Host-block route costs a child window and about 50 binding calls per visible table, a guessed height until ImGui has drawn it twice (a first-frame ImGui table measured up to 35,066 px), and height corrections of up to 3,552 px when one scrolls into view. In advtext nothing draws a table yet. | already backlog (D32.4, D34); this is its evidence |
| **C6** | **Line height and advances a host can match to ImGui's.** (a) `LineHeight` as "the font's own ascent plus descent", or the font numbers to compute it (R9); (b) an option to round advances as ImGui does for a face. | pptmstr's patch hard-codes `_LINE_HEIGHT_EM = 1.05` from Inconsolata's hhea (859 + 190 over 1000) so rows keep their 16 px pitch. Measured advance of Inconsolata at ImGui size 16: ImGui 8.01 px, imtypeset 7.626 px: monospace text in the Document is 4.8 % narrower than ImGui's and its columns do not line up with ImGui-drawn text beside it. No speed in it; it is the first thing visible in `python/spike_bundle/shots/pptmstr-app-imtypeset.png` beside `pptmstr-app-today.png`. | `ImTypesetStyle`; `src/fontlib` for (a) |
| **C7** | **Replacing the last block without the pass over all blocks.** | A streaming block whose styling changes (pptmstr's live paragraph: 271 to 290 replaces against 109 appends in advtext's stream of `sample.md`) is a `ReplaceDocumentBlocks`, which makes the next layout visit every block. Per frame while streaming, description plus edit: 136 us at 1,442 blocks, 173 to 227 us at 118 to 1,722 blocks, so the pass is not what dominates at these sizes; api-document measured 610 us at 10,000. Low priority until a transcript is that long. | `src/blocks.*` (`splice`) |
| **C8** | **A run's tag separate from its style, or overlapping runs stated as allowed.** | A link over bold text needs the host to split runs so each carries both a face and a tag. 0 such links in advtext's six demo files and 0 links at all in pptmstr's 46 session transcripts, so this is a noticed shape, not a measured cost. `convert.py` drops the tag when ranges overlap and counts it. | header comment at least |

Not requested, and why: a cheaper call boundary (3 library calls a frame cost under 1 us of
boundary); `Document.view` (the applications own their child window, follow-tail and context menu;
it was not tried, so nothing is known against it); per-role ink (a `BlockStyle.Color` per kind was
enough in both).

Python-package observations that are not core requests: describing blocks costs 7 us a LITERAL
block and about 30 us a prose block in pptmstr (10.4 ms for 1,442 blocks, 50 to 60 ms for 1,722
prose blocks), and 79 us a block in advtext (2.9 ms for 37), all in the application's own Python
before `_pack`; `Document._pack` itself was not timed apart.
